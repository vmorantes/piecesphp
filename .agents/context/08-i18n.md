# 08 — Internacionalización (i18n)

El sistema es multi-idioma de punta a punta: URLs, mensajes, contenido de BD y
traducción asistida por IA.

## Idiomas soportados

Configurados en `src/app/config/lang.php`:
`es` (por defecto), `en`, `fr`, `de`, `it`, `pt`.
Cada uno necesita `src/app/lang/<code>.php`.

## Cómo se decide el idioma

Tres estrategias, con esta precedencia:

1. **Cookie** (`lang_by_cookie = true`) — cookie `PREFER_LANG_BY_COOKIE`, definida a
   partir del parámetro de URL `i18n`. **Máxima prioridad.**
2. **URL** (`lang_by_url = true`) — primer segmento de la ruta
   (`https://sitio/en/admin/...`). Si el idioma va explícito en la URL, gana sobre
   el navegador.
3. **Navegador** (`lang_by_browser = true`) — `getPreferredLanguageByHeader()` sobre
   `Accept-Language`; define `default_lang`.

Además, un middleware en `index.php` lee la cabecera HTTP
**`PCSPHP-Response-Expected-Language`** y, si viene, fuerza `app_lang` — pensado
para integraciones API/móvil.

El prefijo de idioma de las rutas se obtiene con `get_config('prefix_lang')` y se
antepone a todos los `RouteGroup`.

Helpers de URL: `get_lang_url()`, `convert_lang_url()`, `get_current_langs_urls()`.

## Traducir en código

```php
__($grupo, $mensaje)      // función principal
lang($clave)              // acceso directo a un mensaje
lang2(...)                // variante
```

Ejemplo real: `__(NewsLang::LANG_GROUP, 'Noticias internas')`.

**El segundo argumento es el texto en español**, que actúa como clave y como valor
por defecto. Es decir: escribe la UI en español dentro de `__()` y las traducciones
a otros idiomas se resuelven por grupo.

## Grupos de traducción

Los mensajes se organizan en **grupos**. Constantes de grupo definidas en
`config/constants.php`:

| Constante | Valor |
| :-- | :-- |
| `GENERAL_LANG_GROUP` | `general` |
| `LANG_GROUP` | `public` |
| `GLOBAL_LANG_GROUP` | `global` |
| `ADMIN_MENU_LANG_GROUP` | `sidebarAdminZone` |
| `USER_LOGIN_LANG_GROUP` | `userLogin` |
| `MAIL_TEMPLATES_LANG_GROUP` | `mailTemplates` |
| `MAILING_GENERAL_LANG_GROUP` | `mailingGeneral` |
| `LOGIN_REPORT_LANG_GROUP` | `loginReport` |
| `SUPPORT_FORM_ADMIN_LANG_GROUP` | `supportFormAdminZone` |
| `CROPPER_ADAPTER_LANG_GROUP` | `cropper` |
| `LOCATIONS_LANG_GROUP` | `locationBackend` |

Cada módulo define el suyo en `<Modulo>Lang::LANG_GROUP` (p. ej. `news-lang`).

## Archivos de idioma

### Globales — `src/app/lang/`

```php
<?php
namespace App\LangMessages;
// Hereda los mensajes que están en lang/default.php
$lang = [
    'datatables' => [ 'ASC' => '...', 'DESC' => '...' ],
    'userLogin'  => [ 'WELCOME_MSG' => '<h1>¡Hola!</h1>...' ],
];
return $lang;
```

`default.php` es la base de la que heredan los archivos por idioma. Hay además
subcarpetas por grupo temático (`usersModule/`, `adminZone/`, `app_config/`,
`public/`, `files/`, …).

### De módulo — `src/app/classes/<Modulo>/lang/<code>.php`

Se registran con un `LangInjector`:

```php
namespace News;

use PiecesPHP\Core\Config;
use PiecesPHP\LangInjector;

class NewsLang extends LangInjector
{
    const LANG_GROUP = 'news-lang';

    public static function injectLang()
    {
        $injector = new LangInjector(__DIR__ . '/lang', Config::get_allowed_langs());
        $injector->injectGroup(self::LANG_GROUP);
    }
}
```

`<Modulo>Routes::routes()` llama a `<Modulo>Lang::injectLang()`.
Los módulos con zona pública tienen además `lang/lang-public/`.

## Traducciones dinámicas

Editables desde el panel, persistidas y volcadas a
`src/app/lang/dynamic-translations/` (prefijo de archivo
`dynamic-translations-`). Configuración en `lang.php`:

```php
set_config('DYNAMIC_TRANSLATIONS', [
    'folderName'         => 'dynamic-translations',
    'filePrefix'         => 'dynamic-translations-',
    'dataConfigName'     => 'DYNAMIC_TRANSCALTIONS',
    'lastDateConfigName' => 'DYNAMIC_TRANSLATIONS_UPDATED_AT',
]);
```

Se cargan en `config/final-configurations-includes/add-dynamic-translations.php`,
y al terminar se dispara `BaseEventDispatcher::EVENT_ADD_DYNAMIC_TRANSLATIONS_NAME`.
El módulo que las administra es `PiecesPHP\LocalizationSystem`.

## Traducciones faltantes

El sistema registra las etiquetas sin traducir en
`src/app/lang/missing-lang-messages/`. Para generar el reporte:

```bash
bin/cli scan-missing-lang --exclude-lang=es,en --exclude-group=locationBackend-names
```

Configuración relacionada en `lang.php`: `no_scan_langs`, `no_scan_lang_groups`,
`additional_langs_to_scan`.

## Traducción automática por IA

- Constantes: `API_TRANSLATION_MODULE`, `API_AI_TRANSLATIONS_ACTIVE`,
  `AI_OPENAI`/`AI_MISTRAL`, `AI_MODELS`, `TRANSLATION_AI_LIST`.
- Config: `translationAI`, `translationAIEnable`, `modelOpenAI`, `modelMistral`,
  `OpenAIApiKey`, `MistralAIApiKey`, `GroqAPIKey`.
- En el front, `autoTranslateFromLangGroupHTML` traduce en cliente, ignorando los
  idiomas listados en `autoTranslateFromLangGroupHTMLIgnoreLangs`.

## Localización de formato

- `locale_langs` — códigos locale por idioma (`es` → `es_CO`, `es_ES`, `es_MX`, …),
  con variantes `.utf8`/`.UTF-8` generadas por `get_locale_versions_by_locale`.
- `lc_time_names_mysql` — `SET lc_time_names` que `BaseModel`/`BaseEntityMapper`
  aplican a la conexión según el idioma actual (nombres de meses/días en SQL).
- `format_date_lang` y `format_date_lang_sql` — formatos de fecha PHP y MySQL por
  idioma. Helper: `get_default_format_date()`.
- `get_fomantic_flag_by_lang(code, size, opacity)` — HTML de la bandera Fomantic UI.
